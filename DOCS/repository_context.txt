## File: .roo/rules-code/AGENTS.md
```markdown
 1: # Project Coding Rules (Non-Obvious Only)
 2: 
 3: The root `AGENTS.md` is the authority. This file only adds coding notes and
 4: must not contradict it.
 5: 
 6: - Always obtain the main plugin class through
 7:   `Algolia_Woo_Indexer::get_instance()`, never by direct instantiation
 8: - **There is no AJAX in this plugin.** Do not add `wp_send_json_error()`,
 9:   `wp_ajax_*` hooks or an AJAX nonce helper. Writes are plain admin POSTs
10:   handled on `admin_init`
11: - Every write path pairs a nonce check from `Algolia_Verify_Nonces` with
12:   `current_user_can( 'manage_options' )`. Both are required. Pass the
13:   capability as a string literal, because a class constant trips
14:   `WordPress.WP.Capabilities.Undetermined` in PHPCS
15: - Use `Algolia_Verify_Nonces::verify_settings_nonce()` and
16:   `verify_send_products_nonce()` rather than calling `wp_verify_nonce()`
17:   directly. Both return `bool` and both `wp_die()` with a 403 on failure
18: - Read `$_POST` via `filter_input()`, then `wp_unslash()`, then
19:   `sanitize_text_field()`. For the array-shaped settings fields, use
20:   `Algolia_Woo_Indexer::get_posted_setting()`
21: - Never echo markup from `admin_init`, from `init()` or at file scope. Use
22:   `Algolia_Check_Requirements::queue_admin_notice()`, which escapes the
23:   already-translated message for you
24: - Read the connection settings through
25:   `Algolia_Woo_Indexer::get_algolia_settings()`, not scattered
26:   `get_option()` calls
27: - Record building lives inline in
28:   `Algolia_Send_Products::send_products_to_algolia()`. There is no
29:   `prepare_product_data()` method. Fields are `objectID`, `product_name`,
30:   `product_image`, `short_description`, `regular_price`, `sale_price`,
31:   `on_sale`
32: - Plugin text domain is `algolia-woo-indexer` everywhere, and must match
33:   the plugin directory name for translations to load
34: - Constants are **global** `define()`s at the top of
35:   `classes/class-send-products.php`, not class constants:
36:   `ALGOWOO_DB_OPTION`, `ALGOLIA_API_KEY`, `ALGOLIA_APP_ID`,
37:   `ALGOLIA_SEARCH_API_KEY`, `INDEX_NAME`,
38:   `AUTOMATICALLY_SEND_NEW_PRODUCTS`, `CHANGE_ME`. Prefix any new constant
39:   you add
40: - `ALGOLIA_API_KEY` is `_admin_api_key` and holds the **Write** key. The
41:   legacy suffix is kept so saved keys keep working. Do not rename it
42: - Database options use the prefix pattern `ALGOWOO_DB_OPTION . SUFFIX`, for
43:   example `_algolia_woo_indexer_application_id`
44: - Core functionality assumes WooCommerce is active. There are no fallbacks
45: - Product price extraction differs by type in
46:   `get_product_type_price()`: `simple` uses the sale and regular price
47:   getters, `variable` uses `get_variation_sale_price( 'min', true )` and
48:   `get_variation_regular_price( 'max', true )`. Everything else returns `0`
49: - Add `@SuppressWarnings(PHPMD.StaticAccess)` to the docblock of any new
50:   static hook callback that calls other classes statically, otherwise
51:   Codacy blocks the merge
```

14: 	 *
15: 	 * @return Built_In_Functions

18: 		global $algowoo_built_ins;
19: 		return $algowoo_built_ins;

21: 	/**
22: 	 * Replace a built-in function for plugin code until the test ends.
23: 	 *
24: 	 * @param string   $name     Built-in function name, without a namespace.
25: 	 * @param callable $callback Replacement receiving the original arguments.
26: 	 * @return void
27: 	 */
28: 	protected function override_built_in( $name, callable $callback ) {
29: 		$this->built_in_functions()->override( $name, $callback );
30: 	}
31: 	/**
32: 	 * Make filter_input( INPUT_POST, ... ) read from the given array.
33: 	 *
34: 	 * Mirrors the real behaviour for FILTER_DEFAULT: a missing field is null,
35: 	 * and a value whose shape does not match FILTER_REQUIRE_ARRAY is false.
36: 	 *
37: 	 * @param array $post Simulated POST data.
38: 	 * @return void
39: 	 */
40: 	protected function set_post_data( array $post ) {
41: 		$this->override_built_in(
42: 			'filter_input',
43: 			static function ( $type, $var_name, $filter = FILTER_DEFAULT, $options = 0 ) use ( $post ) {
44: 				unset( $filter );
45: 				if ( INPUT_POST !== $type || ! array_key_exists( $var_name, $post ) ) {
46: 					return null;
47: 				}
48: 				$value         = $post[ $var_name ];
49: 				$require_array = is_int( $options ) && ( $options & FILTER_REQUIRE_ARRAY );
50: 				if ( is_array( $value ) !== (bool) $require_array ) {
51: 					return false;
52: 				}
53: 				return $value;
54: 			}
55: 		);
56: 	}
57: 	/**
58: 	 * Remove every built-in override.
59: 	 *
60: 	 * @return void
61: 	 */
62: 	protected function reset_built_ins() {
63: 		$this->built_in_functions()->reset();
64: 	}

## File: .roo/rules-architect/AGENTS.md
```markdown
 1: # Project Architecture Rules (Non-Obvious Only)
 2: 
 3: The root `AGENTS.md` is the authority. This file only adds architecture
 4: notes and must not contradict it.
 5: 
 6: - Plugin follows WordPress plugin architecture, not MVC. All classes are
 7:   utility/service classes
 8: - **There is no AJAX anywhere in this plugin.** Both the settings form and
 9:   the "Send products" form are plain POSTs to
10:   `options-general.php?page=algolia-woo-indexer-settings`, handled on
11:   `admin_init`
12: - Singleton on the main class exists so the activation/deactivation hooks
13:   can be bound to one instance, and so `init()` registers its hooks only
14:   once. Not because of AJAX
15: - Mostly static methods, but not "no dependency injection":
16:   `Algolia_Woo_Indexer` takes `AlgoliaConnectionStatus` as an optional
17:   injected constructor dependency. New collaborators should follow that
18:   pattern rather than adding more static coupling
19: - Static access is deliberate and is suppressed per-callback with
20:   `@SuppressWarnings(PHPMD.StaticAccess)`, because Codacy runs PHPMD and
21:   blocks merges. Do not refactor to DI just to silence it
22: - Plugin settings stored as individual prefixed options, not a single
23:   serialized array
24: - Activation/deactivation hooks in the main file, but the actual logic is
25:   delegated to class methods
26: - No autoloader. Classes are included manually via `require_once` in the
27:   main file
28: - WordPress hooks are the integration points, not observer patterns or
29:   events
30: - The `save_post` auto-index hook is registered outside `is_admin()` on
31:   purpose so REST, WP-CLI and scheduled publishes are indexed. Do not move
32:   it inside
33: - All admin output is deferred to `admin_notices`, usually through
34:   `Algolia_Check_Requirements::queue_admin_notice()`. Never echo from
35:   `admin_init` or at file scope
36: - Algolia client is instantiated fresh each time. No connection pooling or
37:   reuse
38: - Product data transformation happens in loops without caching, and
39:   `saveObjects()` is called once with every record and no chunking. This is
40:   the main scaling bottleneck
```

## File: .roo/rules-debug/AGENTS.md
```markdown
 1: # Project Debug Rules (Non-Obvious Only)
 2: 
 3: The root `AGENTS.md` is the authority. This file only adds debugging notes
 4: and must not contradict it.
 5: 
 6: - **There is no AJAX in this plugin.** There is no network tab to check and
 7:   no JSON error response. Every failure surfaces as a WordPress admin
 8:   notice on the settings page, or not at all
 9: - Admin notices are queued, not echoed. If a message is missing, check that
10:   the code path called
11:   `Algolia_Check_Requirements::queue_admin_notice()` before `admin_notices`
12:   fires. Anything echoed from `admin_init` or file scope is a bug
13: - The WordPress debug log is the only log output. The plugin writes no log
14:   files of its own
15: - `Algolia_Check_Requirements::check_unmet_requirements()` queues notices
16:   for missing `mbstring`, `mb_ereg_replace` or `curl`, but it does **not**
17:   block activation. A version mismatch likewise only queues a notice
18: - `Algolia_Send_Products::send_products_to_algolia()` has three silent
19:   early returns. Check them in order:
20:   1. `vendor/autoload.php` missing, guarded by `file_exists()`
21:   2. `Algolia_Check_Requirements::check_algolia_input_values()` returning
22:      `false` because a credential or the index name is empty
23:   3. `wc_get_products()` returning nothing
24: - A failed send surfaces as a caught `AlgoliaException` from
25:   `saveObjects()`, or as a `NullResponse`. Detect the latter with
26:   `'Algolia\AlgoliaSearch\Response\NullResponse' === get_class( $result )`
27: - The connection check is a single `wp_remote_post()` from
28:   `AlgoliaConnectionStatus` to
29:   `https://{appId}.algolia.net/1/indexes/{index}/query` with an empty
30:   query, using the **Search** API key. It is not `listApiKeys()`. Results
31:   are cached per request, and `sanitize_connection_diagnostic()` redacts
32:   both keys, so a diagnostic string will never show you the real key
33: - A send that works manually but not automatically means the auto-send
34:   option is not `'1'`. `init()` only registers `save_post` when it is, and
35:   `send_new_product_to_algolia()` additionally ignores anything that is not
36:   a published post of type `product`
37: - `wp_die()` with a 403 from `Algolia_Verify_Nonces` means either an
38:   expired nonce or a user without `manage_options`. Both verifiers check
39:   both
40: - There is no chunking. A timeout or memory exhaustion on a large catalogue
41:   is the expected failure mode of the single `saveObjects()` call
42: - `uninstall.php` only runs when `WP_UNINSTALL_PLUGIN` is defined, and it
43:   deletes options by literal suffix. An option added without a matching
44:   `delete_option()` line will be orphaned
45: - Unit tests (`composer test`) cover the plugin logic with WordPress and
46:   Algolia mocked; see "Unit tests" in the root `AGENTS.md`. Integration
47:   behaviour, such as real hooks, the database or Algolia itself, still has to
48:   be reproduced inside a real WordPress plus WooCommerce install
```

 1: <?php
 2: /**
 3:  * Registry of overrides for PHP built-in functions called by the plugin.
 4:  *
 5:  * @package algolia-woo-indexer
 6:  */
 7: namespace Algowoo\Tests\Support;
 8: /**
 9:  * Lets a test replace the result of a PHP built-in function for plugin code.
10:  *
11:  * The plugin classes live in the Algowoo namespace and call built-ins such as
12:  * filter_input() unqualified, so PHP resolves Algowoo\filter_input() first.
13:  * tests/shims.php defines those namespaced functions. Because they are plain
14:  * functions, they reach the shared instance through the global
15:  * $algowoo_built_ins, created in tests/bootstrap.php. Tests use the
16:  * Overrides_Built_Ins trait rather than this class directly.
17:  */
18: final class Built_In_Functions {
19: 	/**
20: 	 * Active overrides, keyed by built-in function name.
21: 	 *
22: 	 * @var array<string, callable>
23: 	 */
24: 	private $overrides = array();
25: 	/**
26: 	 * Replace a built-in function until the next reset().
27: 	 *
28: 	 * @param string   $name     Built-in function name, without a namespace.
29: 	 * @param callable $callback Replacement receiving the original arguments.
30: 	 * @return void
31: 	 */
32: 	public function override( $name, callable $callback ) {
33: 		$this->overrides[ $name ] = $callback;
34: 	}
35: 	/**
36: 	 * Call the override for a built-in, or the real built-in when none is set.
37: 	 *
38: 	 * @param string $name Built-in function name.
39: 	 * @param array  $args Arguments passed by the plugin code.
40: 	 * @return mixed
41: 	 */
42: 	public function call( $name, array $args ) {
43: 		if ( isset( $this->overrides[ $name ] ) ) {
44: 			return ( $this->overrides[ $name ] )( ...$args );
45: 		}
46: 		return ( '\\' . $name )( ...$args );
47: 	}
48: 	/**
49: 	 * Remove every override.
50: 	 *
51: 	 * @return void
52: 	 */
53: 	public function reset() {
54: 		$this->overrides = array();
55: 	}
56: }

257:    class comments must use `/** */`

259: ## Development Commands
260: 
261: - Install dependencies: `composer install`
262: - Run the unit tests: `composer test`
263: - Coverage report: `composer test:coverage` (needs the `pcov` extension)
264: - Run PHP_CodeSniffer: `composer phpcs`. `phpcs.xml` lists no files, so a
265:   bare `vendor/bin/phpcs` errors; pass a path (`vendor/bin/phpcs .`)
266: - Fix coding standards: `composer phpcbf`. `phpcs-autofix.yml` also
267:   applies automatic fixes in CI
268: - Run PHPMD: `composer phpmd`
269: - **GitHub Actions are pinned to full commit SHAs** with a trailing version
270:   comment (`uses: actions/checkout@<40-char sha> # v7.0.1`), never to a tag
271:   such as `@v7`, because tags can be moved. Dependabot's `github-actions`
272:   entry updates the SHA and the comment together. Pin new actions the same
273:   way. Resolve a SHA with
274:   `git ls-remote https://github.com/<owner>/<repo> 'refs/tags/<tag>^{}'`,
275:   falling back to `refs/tags/<tag>` for lightweight tags

277: ## Unit tests
278: 
279: - PHPUnit 13 with Brain Monkey and Mockery, with no WordPress install.
280:   `tests/Unit/*_Test.php` holds the tests and `tests/Support/` holds the
281:   shared base class and helpers. Class and file names use WordPress style
282:   (`Send_Products_Test`) so PHPCS passes without exclusions
283: - CI: `.github/workflows/phpunit.yml` runs the suite on PHP 8.5, **fails
284:   below 90% line coverage**, and runs PHP 8.6 as a non-blocking job. The
285:   only uncovered lines are the `exit;` direct-access guards
286: - `tests/bootstrap.php` defines `ABSPATH` to point at `tests/fixtures/wordpress/`,
287:   whose `wp-admin/includes/plugin.php` is deliberately empty. `Test_Case`
288:   loads the class files once per process, in the main plugin file's order.
289:   The global `define()`s mean they can never be loaded twice
290: - **PHP built-ins are faked through namespaced shims, not Brain Monkey.**
291:   The plugin calls `filter_input()`, `extension_loaded()`,
292:   `function_exists()`, `file_exists()` and `version_compare()` unqualified
293:   inside `namespace Algowoo`, so `tests/shims.php` defines `Algowoo\*`
294:   versions that delegate to a `Built_In_Functions` instance held in the
295:   global `$algowoo_built_ins`, created in `tests/bootstrap.php`. In tests,
296:   use `$this->override_built_in()` and `$this->set_post_data()` from the
297:   `Overrides_Built_Ins` trait; the latter simulates `$_POST`, because
298:   `filter_input()` never sees request data under the CLI. Shims must exist
299:   before any plugin file loads, because PHP caches how an unqualified call
300:   resolves. To fake another built-in, add a shim there
301: - **Brain Monkey trap:** when a function is stubbed with `Functions\when()`
302:   in `setUp()`, a later `Functions\expect()` for that function in the test
303:   is silently ignored, including `->never()`. Record calls in the `when()`

251: 		/**
252: 		 * Read a single submitted settings value, unslash it and sanitize it.
253: 		 *

258: 		private static function get_posted_setting( $field_name, $key ) {
259: 			$field = filter_input( INPUT_POST, $field_name, FILTER_DEFAULT, FILTER_REQUIRE_ARRAY );

272: 		 * @return array Sanitized settings data.

282: 			return $valid;
