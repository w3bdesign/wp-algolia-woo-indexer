# Project Documentation Rules (Non-Obvious Only)

The root `AGENTS.md` is the authority. This file only adds documentation
notes and must not contradict it.

- `algolia-woo-indexer.php` holds only the plugin headers, the
  `require_once` list, the WooCommerce HPOS/Blocks declaration and the
  `get_instance()` bootstrap. All logic lives in `classes/`
- `DOCS/repository_context.txt` is generated by the Repomix GitHub workflow
  on pushes to `main`. Do not edit it by hand, and treat it as a snapshot
  that may lag the code
- There are six classes, not four: `Algolia_Woo_Indexer`,
  `Algolia_Send_Products`, `Algolia_Verify_Nonces`,
  `Algolia_Check_Requirements`, `AlgoliaConnectionStatus` and
  `AlgoliaSettingsFields`. The split is by responsibility, not MVC
- Class files use the WordPress `class-name.php` convention but all live in
  the `Algowoo` namespace. There is no autoloader
- **Composer is a runtime dependency, not just tooling.**
  `algolia/algoliasearch-client-php` is required by
  `Algolia_Send_Products`. PHPCS is the only dev-only dependency
- Translation files in `languages/` use the standard WordPress gettext
  pipeline with the text domain `algolia-woo-indexer`
- The settings structure is documented in code comments and in the root
  `AGENTS.md`, not in any external doc
- Version requirements are declared in four places and must agree: the
  plugin header, `ALGOLIA_MIN_PHP_VERSION` / `ALGOLIA_MIN_WP_VERSION` in
  `classes/class-check-requirements.php`, `readme.txt` and `README.md`.
  Current values are WordPress 7.1+, PHP 8.4+, WooCommerce 11.2.1+
- Licence is AGPL-3.0, declared in `LICENSE`, `readme.txt`,
  `algolia-woo-indexer.php`, `composer.json` and `README.md`
- Constants are global `define()`s at the top of
  `classes/class-send-products.php`, not class constants, and they are
  unprefixed. This is a known wart
- `README.md` claims products without a category are skipped. **No code in
  `classes/` filters on categories.** Treat that README line as unverified
  and do not repeat it as fact
